Room chat, with the parts a small group needs.

One server runs the rooms, the files, and the host console. There is no second service to install and no account to create.

One room, or several

The main room holds everyone. Named rooms hold up to 20 people and can sit inside one another. Direct threads stay between two.

Messages stay here

Every message lands in a SQLite file on this machine. No relay, no cloud copy, no analytics.

Files up to 20 MB

Images show in the thread. Other files download. The browser shrinks an oversized photo before upload.

Quotes and reactions

Reply with a quote, react with any emoji, edit or delete your own text. A deleted message leaves a quiet placeholder.

A console for the host

Checks, people, rooms, logs, settings, and a stop button, in a browser. A host name and host password open it, and it answers on this machine only by default.

Files from phones

LocalSend devices on the same network send files straight into the room. No cable, no cloud drive.

Two commands on the host.

Python 3.10 or newer. No build step, no database server, no Node toolchain. The setup screen opens in a browser on the machine which runs the server.

From source

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python server.py

On Windows use .venv\Scripts\activate. The console then opens at http://127.0.0.1:7284/console.

Other ways to start

systemdUnit file and installer in deploy/.
launchdPlist for a login session on macOS.
DockerImage and compose file with a fixed data volume.
WindowsBatch launcher for a desktop shortcut.
DesktopWindow and server builds for Windows, macOS, and Linux in the release.
ProxyCaddy and nginx examples with the stream settings.

Service notes and the full settings list live in the repository and on the how it works page.
